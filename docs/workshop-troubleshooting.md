# ローカル版が起動しないときの対処手順（Windows）

対象：受講生向けの「ITパスポート勉強会_Windows.zip」。
ZIP内にも、この手順を「教材」フォルダーに同梱しています。

## 最初に確認すること

1. ZIPを右クリックして「すべて展開」してください。ZIP内を開いただけでは準備完了ではありません。
2. 展開先の `it-passport-workshop` に、`起動.cmd`・`環境チェック.cmd`・`起動ログ.cmd`・`public`・`scripts`・`workshop` があることを確認します。
3. Node.jsはダウンロードだけでなく、インストールまで完了させます。
4. 起動済みのアプリがあれば、その黒い画面で `Ctrl+C` を押して終了します。
5. `環境チェック.cmd` をダブルクリックします。

チェックはNode.jsの有無とバージョン、必要ファイル、フォルダーへの書き込み、SQLite、問題JSON、
既存DBの読み取り、使用するポートを確認します。問題や学習履歴は変更せず、診断ログと一時的な書き込み確認ファイルを作成します。
書き込み確認ファイルは確認後に削除します。
ポート確認はアプリを停止した状態で行ってください。

## 診断結果と対処

| 表示・症状 | 意味 | 対処 |
|---|---|---|
| `Result: PASS (0 failed checks)` | 起動前の確認を通過 | 次の「起動ログを取る」へ進む。ブラウザ表示や会社の制限まですべて保証する結果ではありません |
| `E_NODE_MISSING` | Node.jsが見つからない | Node.js 22.13以上をインストールし、起動ファイルを開き直す。インストール済みならPCを再起動して再確認 |
| `E_NODE_VERSION` | Node.jsが古い | 22.13以上へ更新する。ログの `Node path` で古いNode.jsを参照していないか講師と確認 |
| `E_FILES` | 必要なファイルがない | ZIP全体を新しいフォルダーへ展開し直す。起動ファイルだけ移動しない |
| `E_WRITE`、`EACCES`、`EPERM` | ログやDBを書き込めない | 自分で書き込める別フォルダーへ展開し直す。会社・学校の管理PCでは管理者へ確認 |
| `E_SQLITE` | Node.jsのSQLite機能が使えない | Node.jsのバージョンとインストールを確認し、ログを講師に渡す |
| `E_DATA`、`Unexpected token` | 問題JSONの形式や状態が不正 | 編集前のバックアップと比較する。未編集なら配布ZIPを別フォルダーへ展開し直す |
| `E_DB`、`database is locked` | DBを読めない・別の処理が使用中 | アプリやDB編集ツールを終了して再確認。復旧しなければ削除せずログを講師へ渡す |
| `E_PORT`、`EADDRINUSE` | 通常8790番のポートが使用中 | すでに起動しているアプリを終了する。不明な別のプロセスを無理に終了せず、講師へ相談 |
| `Existing data conflict` | JSONの修正内容と既存DBが異なる | サーバーを止め、`.local/workshop/app.sqlite` を別名へ退避してから起動。新しいDBをJSONから作成する |
| `E_START` | ログ付きサーバー起動に失敗 | 起動ログを講師へ渡す |
| `ExperimentalWarning: SQLite` | 使用中のNode.jsが出す警告 | 後に `Local preview` が出れば起動している。警告だけなら停止原因ではない |

`PORT` 環境変数が設定されているPCでは、その番号を使います。ログに表示されたURLを優先してください。

## 起動ログを取る

1. 通常の `起動.cmd` で動いているサーバーを終了します。
2. `起動ログ.cmd` をダブルクリックします。
3. 起動前の環境チェック後、サーバーを起動し、画面の出力とエラーをログに保存します。
4. `Local preview: http://127.0.0.1:8790` が表示されたら、ブラウザでそのURLを開きます。
5. エラーが出たらそのまま内容を確認し、終了時は `Ctrl+C` を押します。

診断に失敗した場合はサーバーを起動せず、対処が必要な項目をログに残します。
`起動ログ.cmd` の実行中は、別の `起動.cmd` を重ねて実行しないでください。
通常の `起動.cmd` は従来どおりの起動用で、ファイルへのログ保存は行いません。

## ログの場所と講師へ渡すもの

展開先の `.local/logs` フォルダーに保存します。ログは自動送信されません。

| ファイル | 内容 |
|---|---|
| `environment-日時-番号.log` | 環境チェックの結果 |
| `startup-日時-番号.log` | 環境チェックとサーバーの起動出力・エラー |
| `check-bootstrap.log`、`log-bootstrap.log` | Node.jsの場所とバージョン。Node.jsが見つからない場合の記録。次回実行で上書き |

講師には、該当するログと「どのファイルを実行し、何が表示されたか」を渡してください。
ログにはPCのフォルダーパスが含まれるため、講師へ個別に共有します。
ログが作成されない場合は、表示された画面のスクリーンショットを渡してください。

## サーバーは動くがブラウザで表示できない場合

- ログの `Local preview` に表示されたURLをそのまま使います。通常は `http://127.0.0.1:8790` です。
- `localhost` や `https://`、`index.html` のダブルクリックは使いません。
- 黒い画面が閉じていないか確認します。
- `http://127.0.0.1:8790/api/catalog` でJSONが表示されるか確認します。初期配布データでは `count` が300です。
- 会社・学校のPCで制限される場合は、セキュリティ設定を変更せず、講師・管理者に相談します。

DBやJSONを変更した後は、古い学習履歴が残ることがあります。履歴を消す必要があるときは、
「はじめに.md」の手順を講師と確認してください。
